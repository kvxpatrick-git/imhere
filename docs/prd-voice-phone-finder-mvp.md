# PRD: 음성 호출 기반 스마트폰 찾기 앱 (Android MVP)

## 1. 문서 정보
1. 문서명: Product Requirements Document (PRD)
2. 버전: v1.0
3. 기준일: 2026-02-15
4. 대상 릴리즈: v1.0 (MVP)
5. 타깃 플랫폼: Android 우선
6. 제품 원칙: 완전 오프라인 동작, 균형형 품질(정확도/반응속도/배터리)

## 2. 요약
집 안에서 스마트폰을 잃어버렸을 때 사용자가 음성 키워드를 말하면, 폰이 즉시 큰 알림음을 단계적으로 재생하여 위치를 찾게 하는 앱을 제공한다.  
MVP는 `온디바이스 키워드 인식`, `사용자 키워드 커스텀`, `3단계 알림 재생`, `음성 중지`, `무음 강제 재생`, `오탐 방지 옵션`, `배터리 보호 모드`를 필수 범위로 한다.

## 3. 문제 정의
1. 사용자는 집 안에서 폰을 소리 없이 두고 위치를 잊어버리는 상황을 자주 겪는다.
2. 기존 방법(다른 기기 로그인, 전화 걸기, 수동 찾기)은 즉시성이 낮거나 번거롭다.
3. 사용자는 네트워크 연결 없이도 빠르고 안정적으로 “내 폰 울리기”를 원한다.
4. 항상 듣는 기능은 오탐과 배터리 문제를 동반하므로 균형 설계가 필요하다.

## 4. 목표 및 성공 지표
1. 제품 목표
1. 집 안 분실 상황에서 10초 이내 탐색 시작 가능 상태를 제공한다.
2. 인터넷 없이 핵심 기능이 100% 동작한다.
3. 오탐/배터리 부담을 허용 가능한 수준으로 제어한다.

2. 정량 KPI (MVP 출시 후 30일 관측)
1. 키워드 감지 후 알림 재생 시작 지연 P95 1.5초 이하.
2. 오탐률: 일반 가정 환경 기준 12시간당 1회 이하.
3. 배터리 소모: 백그라운드 리스닝 12시간 기준 6% 이하(기기 표준 모드 기준).
4. “찾기 성공” 사용자 이벤트 비율 85% 이상.
5. 앱 크래시 없는 세션 비율 99.5% 이상.

## 5. 대상 사용자
1. 1차 타깃: 일반 Android 사용자.
2. 주요 상황: 집 안에서 폰의 위치를 잊어버린 상황.
3. 사용 맥락: 손이 바쁘거나 시야가 제한된 상태에서도 음성만으로 즉시 호출 가능해야 함.

## 6. 범위
1. MVP 포함 범위 (필수)
1. 온디바이스 키워드 인식으로 분실 찾기 시작.
2. 사용자 키워드/별칭 등록, 변경, 삭제.
3. 감지 즉시 알림 재생.
4. 3단계 재생 시퀀스: 확인음 -> 큰 벨소리 -> 최대 볼륨+진동.
5. 음성 중지 명령(예: “멈춰”) 지원.
6. 무음/진동 모드에서도 강제 재생 옵션.
7. 오탐 방지 옵션(2단계 트리거) 제공.
8. 저전력 배터리 보호 모드 제공.

2. MVP 제외 범위 (비포함)
1. 스마트홈 기기 연동.
2. 가족 계정/원격 타인 제어.
3. 웨어러블 연동.
4. 집 안 공간(방) 기반 존 정책.
5. 클라우드 기반 음성 처리.

## 7. 핵심 사용자 시나리오
1. 기본 찾기 시나리오
1. 사용자는 사전 설정된 키워드를 말한다.
2. 앱이 키워드를 감지한다.
3. 앱이 즉시 1단계 확인음을 재생한다.
4. 사용자가 폰 위치를 못 찾으면 2단계, 3단계로 자동 상승한다.
5. 사용자가 폰을 찾고 “멈춰”를 말하면 재생이 중지된다.

2. 무음 모드 시나리오
1. 폰이 무음/진동 상태여도 “강제 재생 허용”이 켜져 있으면 재생한다.

3. 오탐 방지 시나리오
1. 2단계 트리거가 켜진 경우, 키워드 후 확인 문구까지 일치해야 재생한다.

4. 저전력 시나리오
1. 배터리 임계치 이하에서 감지 강도를 자동 완화한다.
2. 기능 중단 대신 성능을 낮추는 방식으로 연속 사용성을 보장한다.

## 8. 기능 요구사항 상세 (FR)
1. FR-01 온디바이스 키워드 감지
1. 앱은 네트워크 연결 없이 키워드를 감지해야 한다.
2. 감지는 백그라운드에서 동작 가능해야 한다.
3. 수용 기준: 비행기 모드에서 키워드 감지 및 재생 성공.

2. FR-02 사용자 키워드/별칭 관리
1. 최소 1개, 최대 3개 키워드를 등록 가능해야 한다.
2. 금지 규칙: 지나치게 짧은(1음절 등) 키워드, 시스템 예약문구.
3. 변경 즉시 감지 엔진에 반영되어야 한다.
4. 수용 기준: 등록/수정/삭제 후 10초 내 새 설정 반영.

3. FR-03 즉시 알림 재생
1. 감지 성공 시 사용자 조작 없이 자동 재생 시작.
2. 수용 기준: 감지 이벤트 이후 오디오 시작 P95 1.5초 이하.

4. FR-04 3단계 재생 시퀀스
1. 1단계: 짧은 확인음(저음량, 2초 내외).
2. 2단계: 큰 벨소리(중고음량, 10초 내외).
3. 3단계: 최대 볼륨 + 진동(지속 재생, 상한 60초).
4. 사용자가 중지하지 않으면 단계 자동 상승.
5. 수용 기준: 각 단계 전환 타이밍 오차 ±1초 이내.

5. FR-05 음성 중지 명령
1. 재생 중 “멈춰” 등 중지 키워드를 인식하면 즉시 중단.
2. 수용 기준: 중지 명령 인식 후 1초 내 재생 중지.

6. FR-06 무음/진동 강제 재생 옵션
1. 기본값은 ON.
2. ON일 때 분실 찾기 세션에서 미디어/알림 정책을 우회해 재생.
3. 수용 기준: 단말이 무음 상태에서도 재생 성공.

7. FR-07 오탐 방지 옵션 (2단계 트리거)
1. 옵션 OFF: 1단계 키워드만으로 동작.
2. 옵션 ON: 키워드 + 확인 문구 모두 일치 시 동작.
3. 수용 기준: ON일 때 단일 키워드만으로는 동작하지 않아야 함.

8. FR-08 배터리 보호 모드
1. 배터리 임계치(기본 20%) 이하에서 감지 주기/모델 강도 자동 완화.
2. 사용자에게 현재 절전 감지 상태를 표시.
3. 수용 기준: 임계치 도달 시 30초 내 보호 모드 전환.

## 9. 비기능 요구사항 (NFR)
1. 성능
1. 키워드 감지 지연 P95 1.5초 이하.
2. 중지 명령 반응 P95 1.0초 이하.
3. 앱 시작 후 리스닝 준비 시간 5초 이하.

2. 배터리
1. 화면 OFF, 백그라운드 리스닝 12시간 소모 6% 이하 목표.
2. 보호 모드 활성 시 소모 30% 이상 절감 목표.

3. 안정성
1. 리스닝 서비스 비정상 종료 시 자동 복구.
2. 24시간 러닝 중 서비스 생존율 99% 이상 목표.

4. 프라이버시/보안
1. 음성 원본은 외부 전송하지 않는다.
2. 로그는 로컬 저장이 기본이며 사용자 삭제 가능해야 한다.
3. 민감 데이터는 OS 권장 저장소 암호화 정책을 따른다.

## 10. 사용자 경험 및 화면 요구
1. 필수 화면
1. 홈: 현재 리스닝 상태, 시작/중지 토글.
2. 키워드 관리: 키워드 목록/등록/수정/삭제.
3. 찾기 설정: 강제 재생, 오탐 방지, 배터리 보호 모드.
4. 테스트 화면: 키워드 테스트, 샘플 재생.
5. 접근성 화면: 큰 글씨 모드, 단순 레이아웃 토글.

2. 상태 표시
1. Idle.
2. Listening.
3. Triggered.
4. Stopped.
5. Battery Saver Active.

## 11. 권한 및 OS 정책 요구
1. 필수 권한: 마이크, 진동, 포그라운드 서비스 관련 권한.
2. 선택 권한(Android 13+): 알림 권한. 거부 시 핵심 기능은 동작하나 복구 UX가 약화된다.
3. 백그라운드 제약 대응: 포그라운드 서비스 알림을 유지.
4. 배터리 최적화 제외 요청은 명시적 사용자 동의 후 진행.
5. 권한 거부 시 기능 제한과 복구 방법을 UI로 안내.

## 12. 데이터 요구사항
1. 저장 항목
1. 키워드/별칭 설정.
2. 기능 토글 상태(강제 재생, 오탐 방지, 배터리 보호).
3. 호출 로그(시간, 트리거 종류, 성공/중지 결과).

2. 저장 정책
1. 로컬 우선 저장.
2. 로그 보관 기본 30일.
3. 사용자가 즉시 전체 삭제 가능.

## 13. 수용 기준 (Acceptance Criteria)
1. 비행기 모드에서도 키워드 감지-재생-중지가 완료된다.
2. 무음 모드에서 강제 재생 ON 시 반드시 소리가 난다.
3. 2단계 트리거 ON 시 확인 문구 없이 재생되지 않는다.
4. 배터리 20% 이하에서 보호 모드가 자동 활성화된다.
5. 키워드 변경 후 새 키워드만 인식되고 이전 키워드는 비활성화된다.
6. 50회 반복 테스트에서 크래시/ANR이 없어야 한다.

## 14. 테스트 시나리오
1. 정상 시나리오: 표준 발화, 소음 적은 환경.
2. 경계 시나리오: TV 소리, 2인 이상 대화, 유사 발음.
3. 오류 시나리오: 권한 거부, 서비스 강제 종료, 배터리 저전력.
4. 디바이스 시나리오: 저사양/중급/고급 단말 각 1대 이상.
5. 접근성 시나리오: 큰 글씨 모드에서 전 경로 조작 가능 확인.

## 15. 리스크와 대응
1. 리스크: 오탐 증가.
1. 대응: 2단계 트리거 기본 제안, 사용자 환경별 민감도 옵션.

2. 리스크: 백그라운드 제약으로 감지 중단.
1. 대응: 포그라운드 서비스 고정, 자동 재시작 로직, 사용자 가이드.

3. 리스크: 배터리 소모 불만.
1. 대응: 보호 모드 기본 ON, 상태 가시화, 사용 시간대 권장 설정.

4. 리스크: 유사 발음 미탐.
1. 대응: 키워드 품질 가이드와 사전 테스트 플로우 제공.

## 16. 릴리즈 기준
1. P0 버그 0건.
2. 핵심 AC 100% 통과.
3. KPI 사전 측정치가 목표 대비 90% 이상.
4. 개인정보/권한 안내 문구 검수 완료.

## 17. 명시적 가정 및 기본값
1. Android 우선 출시를 기본으로 한다.
2. 완전 오프라인 동작을 절대 요구사항으로 둔다.
3. 품질 전략은 균형형(정확도/반응속도/배터리)이다.
4. 기본 중지 명령어는 “멈춰” 1개로 시작한다.
5. 배터리 보호 임계치는 기본 20%로 시작한다.
